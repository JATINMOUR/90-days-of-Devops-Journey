# Advanced Git & GitHub Commands Cheatsheet

This guide covers advanced operations including stashing, rebasing, cherry-picking, tagging, debugging with bisect, collaboration workflows, GitHub authentication methods, and GitHub Actions CI/CD pipeline setup.

## 1. Stashing

Temporarily save uncommitted changes without creating a commit, allowing you to switch contexts safely.

| Command | Description |
| --- | --- |
| `git stash` | Save uncommitted changes to a temporary stash. |
| `git stash list` | List all stashes in the current repository. |
| `git stash apply` | Apply the most recent stash without removing it from the stash list. |
| `git stash drop` | Delete the most recent stash from the stash list. |

## 2. Rebase and Cherry-pick

Reapply commits on new base branches or port specific commits across branches.

| Command | Description |
| --- | --- |
| `git rebase <branch_name>` | Reapplies commits on top of another base branch. *Note: Avoid rebasing shared public branches as it rewrites history.* |
| `git rebase -i <commit_hash>` | Starts an interactive rebase session starting from a specific commit. |
| `git rebase --abort` | Aborts the current rebase process and returns to the pre-rebase state. |
| `git rebase --continue` | Continues the rebase sequence after resolving merge conflicts. |
| `git rebase --skip` | Skips the current commit during a rebase operation. |
| `git cherry-pick <commit_hash>` | Applies a specific commit from another branch directly onto the current branch. |

## 3. Tagging

Mark specific points in repository history as significant (typically release versions).

| Command | Description |
| --- | --- |
| `git tag <tag>` | Create a lightweight tag. |
| `git tag -a <tag> -m "msg"` | Create an annotated tag with an associated description message. |
| `git push origin --tags` | Push all local tags to the remote repository. |

## 4. Git Bisect (Debugging Bad Commits)

Use binary search through commit history to pinpoint which exact commit introduced a bug.

| Command | Description |
| --- | --- |
| `git bisect start` | Begins binary search process to locate the bug-introducing commit. |
| `git bisect bad` | Marks the current commit as containing the bug ("bad"). |
| `git bisect good <commit>` | Marks a known commit as free of the bug ("good") to set search boundaries. |
| `git bisect reset` | Ends the bisect session and resets workspace to its original state. |

## 5. Collaboration Commands

Inspect changes, trace file line histories, and format repository logs.

| Command | Description |
| --- | --- |
| `git blame <file>` | Shows line-by-line commit history and author information for a file. |
| `git shortlog` | Summarizes repository commit counts and contributions organized by author. |
| `git log --graph` | Displays commit history with an ASCII graph representing branch structures. |
| `git show <commit>` | Displays full details and diff output of a specific commit. |
| `git diff --staged` | Shows line differences between staged changes and the last commit. |
