
## Case Sensitivity & File Naming Conventions

### Case Sensitivity
Linux is case-sensitive; file names, variables, and arrays used in shell scripts are also case-sensitive.

```bash
#!/bin/bash
string1=10
String1=20
echo "The value of string1 is $string1"
echo "The value of String1 is $String1"
```

### File Naming Conventions
1. Maximum length of 255 characters.
2. Can contain alphabets, digits, dots (`.`), and underscores (`_`).
3. System commands or Linux reserved words cannot be used as file names.
4. File system is case-sensitive.
5. **Valid Examples:**
   * `shubham.txt`
   * `Shubham.sh`
   * `Shubham_08112013.sh`
   * `Shubham05.sh`

## Comments

Comments are used to exclude parts of the file from execution. The program interpreter ignores commented lines.

* **Single-line Comments:** Use `#`
* **Multi-line Comments:** Use the **HERE DOCUMENT** feature:

```bash
<<COMMENT1
Your comment line 1
Comment line 2
Blah blah
COMMENT1
```

### Examples

**Single Line Comment (`comments.sh`):**
```bash
#!/bin/bash
# This is a basic shell script by Shubham.
echo "Hello, welcome to The DevOps Learning..." # It will display the message
```

**Multi-line Comment (`multiline_comments.sh`):**
```bash
#!/bin/bash
echo "We are commenting multiple lines"

<<COMMENT1
I am commenting here multiple lines
using HERE DOCUMENT
feature
COMMENT1

echo "Multiline comment done"
```

## Variables

There are two main types of variables in Linux shell scripts:
1. **System Variables**
2. **User Defined Variables (UDV)**

### Naming Conventions for Variables
* Variable names must begin with an alphanumeric character or an underscore (`_`).
* By convention, environment variables (e.g., `PAGER`, `EDITOR`) and internal shell variables (e.g., `SHELL`, `BASH_VERSION`) are UPPERCASE.
* All other variable names should be lowercase to avoid accidentally overriding environmental and internal variables.
